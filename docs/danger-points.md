# Danger Points

## 暗号化境界

- 取引JSONの暗号化・復号はブラウザで行う。
- サーバーは `encrypted_payload` を解釈せず保存・返却だけを行う。
- 店舗、カテゴリ、メモ、明細、OCR文字列、パスフレーズ、導出鍵を平文DB列やログへ追加しない。
- パスフレーズを失うと既存取引を復号できない。サーバー側の復旧手段はない。
- payload version 1 の旧データには、金額式・税率・税額がない場合がある。追加項目は後方互換を維持する。

## レシートOCR

- `/api/receipts/preview` への画像送信は発生するが、preview処理では画像・OCR結果・平文取引をDB保存しない。
- Geminiは `GEMINI_API_KEY` と任意SDKがある場合だけ利用する。失敗時はTesseractへフォールバックする。
- `pytesseract` はPythonラッパーであり、Tesseract本体と `jpn` 言語データは別途必要。
- OCR結果には誤読、日付誤認、合計と明細の不一致、店舗名揺れがある前提で確認画面を維持する。

## 金額式

- 許可するのは数値、加減乗除、単項符号、括弧だけ。
- `eval`、`exec`、JavaScript `Function`、シェル展開は使用禁止。
- 未知文字、累乗、指数表記、ゼロ除算、非有限値、長すぎる式、深すぎる括弧を拒否する。
- 円への丸めと税込内税額の丸めは別処理であり、変更時は境界値テストが必要。
- 演算APIへ送るのは金額式と税率だけ。取引の他項目を追加しない。

## 税率

- 食費8%、その他支出10%、収入0%は手入力時の初期値であり、法的な確定判定ではない。
- 酒類、外食、非課税、混在税率などはカテゴリだけでは確定できないため、ユーザー修正を許可する。
- OCRのカテゴリマスタ由来税率とフロント初期値は完全には統一されていない。

## カテゴリ語彙

- フロント、旧CSV処理、バックエンド分類、過去の暗号化データでカテゴリ名が一致しない場合がある。
- 例: `交通` と `交通費`、`医療` と `医療費`、`副業` と `副収入`。
- 既存値を無断で置換しない。統一する場合は明示的な対応表、移行方針、集計テストが必要。

## 集計

- 取引合計は必ず1回だけ計上する。
- 明細の全金額が有効で、明細合計が取引合計と一致するときだけ明細カテゴリへ配分する。
- 不一致・明細なしの場合は取引本体のカテゴリと金額へフォールバックし、件数を画面に表示する。
- 復号失敗と不正日付は集計対象外として明示する。0円へ暗黙変換しない。

## ローカルデータ

- `backend/data.db` と `backend/uploads/` はGit管理外。
- DBモデル変更前にローカルDBのバックアップと移行方針を用意する。
- `scripts/sync_local.sh` は未コミット変更がある場合に停止する。自動stash・reset・cleanは行わない。

## CIと依存

- CI基準はNode.js 22、Python 3.12。
- バックエンド直接依存はrequirementsファイルで固定し、アプリ全体のimportをCIで確認する。
- 依存更新は単独スプリントにし、OCR画像ライブラリとNumPy/OpenCVの互換性を確認する。

## エージェント運用

- 変更前に対象ファイル、受入条件、検証方法を示す。
- 1スプリント1責務を維持する。
- CI失敗をテスト削除や検証弱化で隠さない。
- 利用制限やツール移行前に `scripts/create_handoff.sh` で状態を引き継ぐ。
